## Reporting a Vulnerability

The project team takes security seriously. We appreciate your efforts to
responsibly disclose your findings, and will make every effort to acknowledge
your contributions.

To report a security vulnerability, please use the following process:

. **DO NOT** open a public issue
. mail security@example.com with:
   - Type of issue (e.g., buffer overflow, SQL injection, cross-site scripting)
   - ull paths of source file(s) related to the issue
   - Location of affected source code (tag/branch/commit or direct URL)
   - Step-by-step instructions to reproduce the issue
   - Proof-of-concept or exploit code (if possible)
   - Impact of the issue

You should receive a response within  hours. If for some reason you do not,
please follow up via email to ensure we received your original message.

## Preferred Languages

## Disclosure Policy

When we receive a security report, the process is:

. Confirm the problem and determine affected versions
. udit code to find similar problems
. Prepare fixes for all supported versions
. Release patches as soon as possible
